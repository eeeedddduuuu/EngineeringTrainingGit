## 四、Bug 修复记录

| 序号 | 问题 | 原因 | 修复方案 |
|:--:|------|------|------|
| 1 | `str \| None` 语法报错 | Python 3.9 不支持联合类型语法 | 替换为 `Optional[str]`，影响 3 个 schema 文件 |
| 2 | 注册接口 500 | `passlib 1.7.4` 与 `bcrypt 5.0` 不兼容 | 用原生 `bcrypt.hashpw` / `bcrypt.checkpw` 替换 |
| 3 | `/api/auth/me` 始终 401 | `__extract_token` 定义在调用者之后，且未用 `Header()` | 移至函数前 + 使用 `Header(default="")` 提取 |
| 4 | `/api/auth/me` 仍 401 | 未剥离 `Bearer ` 前缀 | 添加 `startswith("Bearer ")` 判断并截取 |
| 5 | 启动时数据表不存在 | `main.py` 缺少建表逻辑 | 添加 `@app.on_event("startup")` 调用 `Base.metadata.create_all` |
| 6 | 知识库检索 500 | Chroma metadata 中 tags 为 JSON 字符串，Pydantic 期望 list | `search()` 中 `json.loads` 反序列化 tags |

## 九、经验与反思

1. **Python 版本兼容**：团队使用 3.9，新语法 `str | None` 需用 `Optional[str]`，项目初期应统一版本
2. **依赖版本冲突**：`bcrypt 5.x` 不兼容 `passlib`，直接用原生 bcrypt 更稳定
3. **分支策略**：从空白 `git init` 开始的代码无法合并到已有仓库，必须基于 `develop` 创建分支
4. **HuggingFace 网络**：国内开发需配置镜像，文档中已说明
5. **Chroma metadata 类型**：存储时 `json.dumps` 的字段读回后仍是字符串，需反序列化
