## 五、集成测试 — 失败案例（3个）

### F-001：知识库搜索 — 中文 URL 编码导致无响应

| 项目 | 内容 |
|------|------|
| **输入** | 在 Streamlit 前端搜索框输入中文关键词（如"短视频脚本"） |
| **失败现象** | 点击搜索后前端卡死，无任何响应或错误提示 |
| **根因分析** | `frontend/app.py` 中 API 调用使用字符串拼接 URL：`f"/knowledge/search?q={q}&top_k={top}"`。中文字符未经过 URL 编码，直接拼入 URL 导致 httpx/requests 发送请求时编码异常，请求未能到达后端 |
| **优化方案** | 改为 `api("/knowledge/search", "GET", {"q": q.strip(), "top_k": top})`，使用 `params` dict 让 httpx 自动处理 URL 编码；同时添加 `st.session_state` 持久化搜索结果，避免 Streamlit 重渲染丢失；增加 `if r is None` 连接失败处理和分状态码错误提示 |
| **优化后结果** | ✅ 中文关键词正常搜索，结果持久化显示，连接失败有明确提示 |
| **关联提交** | `c48b37f` — `fix(p5): 知识库搜索无响应修复` |

### F-002：Embedding 模型加载 — HuggingFace SSL 超时 30s+

| 项目 | 内容 |
|------|------|
| **输入** | 启动后端，首次加载 `BAAI/bge-small-zh-v1.5` 模型 |
| **失败现象** | 知识库搜索耗时 30s+，日志显示 HuggingFace 连接超时；国内网络环境下 SSL 证书验证失败 |
| **根因分析** | `SentenceTransformer(self._model_name)` 默认尝试连接 `huggingface.co` 检查模型更新。国内网络环境访问 HuggingFace 不稳定，SSL 握手频繁失败，每次初始化都要等待超时后才能回退到本地缓存 |
| **优化方案** | 添加 `local_files_only=True` 参数，强制仅使用本地缓存模型，跳过网络检查 |
| **优化后结果** | ✅ 模型加载从 30s+ 降至 ~2s，不再受网络影响 |
| **关联提交** | `4135531` — `fix(backend): SentenceTransformer local_files_only=True` |

### F-003：知识库语义匹配 — 部分查询 Top-1 精度不足

| 项目 | 内容 |
|------|------|
| **输入** | 查询"小红书种草文案"，期望返回种草文案相关内容 |
| **失败现象** | Top-1 返回通用词条"小红书"（相似度 0.630），未匹配到"种草文案"语义；查询"B站创作教程"的 Top-1~3 均为B站相关但未涉及"创作教程" |
| **根因分析** | `bge-small-zh-v1.5` 是小模型（384维），对细粒度语义区分能力有限。"小红书"本身的 embedding 向量与"种草文案"组合后，模型更偏向匹配"小红书"而非"种草"。158条样本中缺乏专门的"种草文案"条目也是原因之一 |
| **优化方案** | 1) 短期：补充5-8条种草文案/创作教程相关的专门样本；2) 中期：升级为 `bge-large-zh-v1.5`（1024维），预计 Top-1 命中率可提升至 90%+；3) 长期：混合检索（语义 + BM25 关键词），对短查询补充关键词匹配 |
| **优化后结果** | ⏳ 本次未实施（属于进阶优化），当前 80% Top-1 命中率已满足基本使用 |
| **关联评估** | 见第二节，10个查询中2个语义匹配不足 |
