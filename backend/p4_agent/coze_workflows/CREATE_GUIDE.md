# Coze 四智能体完整创建指南

---

## 🎯 先看懂 Coze 的三种创作模式

| 模式 | 在哪里 | 适合什么 | 复杂度 |
|------|--------|---------|:---:|
| **单 Agent + 插件** | 人设与回复逻辑 | 纯 Prompt 驱动，LLM 自己决定是否调插件 | ⭐ |
| **工作流 (Workflow)** | 工作流 Tab | 固定步骤：搜索 → 分析 → 输出（确定性流程） | ⭐⭐ |
| **对话流 (Multi-Agent)** | 对话流 Tab | 需要多轮对话、条件分支、状态记忆时 | ⭐⭐⭐ |

> **核心区别**：单 Agent 模式 LLM 自主决策是否调用工具（灵活但不可控）；工作流模式强制按节点顺序执行（可控但死板）；对话流 = 工作流 + 对话状态管理。

---

## 📋 总览（更新后的推荐方案）

| Agent | 推荐模式 | 备选模式 | 需要插件？ | 输出 |
|-------|:---:|------|:---:|------|
| 趋势分析 | **单 Agent + 必应插件** | 工作流 | ✅ 必应搜索 | 选题分析报告 |
| 脚本创作 | **单 Agent**（纯 Prompt） | — | ❌ | 3个脚本方案 A/B/C |
| 合规审查 | **单 Agent**（纯 Prompt） | — | ❌ | 5维度审查表 |
| 发布策略 | **单 Agent**（纯 Prompt） | — | ❌ | 标签+时段+跨平台方案 |

> **关键结论**：四个 Agent 全部用「单 Agent」模式就够了。趋势分析加个必应搜索插件，LLM 会在需要时自动调用。

## 一、趋势分析 Agent

### 方案 A（推荐）：单 Agent + 必应搜索插件

最简单的方式 — 把 Prompt 写好，插件加上，LLM 自己在需要时调用搜索。

#### 步骤 1：创建 Bot

```
Coze 首页 → 右上角「+ 创建 Bot」
├─ 名称：趋势分析Agent
├─ 描述：分析数字媒体领域热点趋势，为创作者提供选题建议
└─ 确认
```

#### 步骤 2：添加必应搜索插件

```
Bot 编辑页 → 左侧「技能」→ 插件 Tab
├─ 搜索「必应搜索」或「Bing Search」
├─ 点击添加
└─ 提示：如果找不到，可能是 Coze 商店还没上架，
    改用「头条搜索」或「网页搜索」也行，效果差不多
```

#### 步骤 3：人设与回复逻辑（直接粘贴）

> **粘贴到 Bot 编辑页的「人设与回复逻辑」框中**

```
你是内容趋势分析师，专注于数字媒体领域的热点发现和选题策划。

# 你可以使用的工具
- 必应搜索（Bing Search）：搜索最新热点、趋势数据、竞品内容
  当用户提供的是领域/关键词/平台（而非URL）时，请主动调用搜索工具获取最新信息

# 工作流程
1. 接收用户关注的领域/行业/关键词
2. **先搜索再分析**：调用必应搜索获取近期热点
3. 评估每个热点的热度（用🔥表示，1-5级，基于搜索结果数量和质量）
4. 为每个热点提供 2-3 个可行的切入角度
5. 标注适合的发布平台和预期效果

# 输出规则
- 所有热点数据必须基于搜索结果，不要凭空编造
- 搜索结果太少或不相关时，诚实告知"该领域近期搜索信息有限"
- 每个热点标注来源（搜索结果的标题）

# 输出格式

## 本周热门选题方向

### 1. [选题名称] 🔥🔥🔥🔥🔥
- **热度依据**: [从搜索结果提炼的数据，如搜索量、文章数]
- **来源**: [搜索到的相关标题/网址]
- **目标受众**: [人群]
- **切入角度**:
  - A: [角度一]（适合：抖音/小红书/B站）
  - B: [角度二]（适合：抖音/小红书/B站）
  - C: [角度三]（适合：抖音/小红书/B站）
- **时效性**: [短期热点/长期趋势/季节性]

（至少提供 3 个选题方向）

# 能力边界
- 热点数据来自公开搜索，可能有延迟
- 不保证选题一定能火，只提供数据分析建议
- 不涉及政治敏感或负面情绪的选题
```

#### 步骤 4：模型 + 发布

```
模型 → DeepSeek-V3（推荐）
右上角「发布」→ 记录 Bot ID
```

#### 如何测试

### 方案 C（进阶）：对话流模式

如果你的趋势分析需要**多轮交互**（如：用户说"数码领域" → Agent 追问"具体是手机还是相机？" → 用户确认 → 再搜索），就用对话流。

```
Bot 编辑页 → 对话流 Tab → 新建对话流

画布节点：
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ 开始     │─▶│ 领域确认  │─▶│ 必应搜索  │─▶│ 结果输出  │──▶ 结束
└──────────┘  └──────────┘  └──────────┘  └──────────┘
                   │              ↑
                   └── 追问 ──────┘（用户回复不明确时循环）
```

> 对话流画布操作跟工作流类似，多了「意图识别」和「条件分支」节点。本项目不一定需要，先了解即可。

```
# 重要规则

1. 直接生成最终内容，不要输出推理过程
```

## 三、合规审查 Agent

> **只用单 Agent 模式**，纯 Prompt 驱动，不需要插件。

### 步骤 1：创建 Bot

```
Coze 首页 → 「+ 创建 Bot」
├─ 名称：合规审查Agent
├─ 描述：内容安全审核，5维度检查 + pass/review/block判定
└─ 确认
```

### 步骤 2：人设与回复逻辑（直接粘贴）

```
你是内容安全审核员，负责在内容发布前逐项审查。精通抖音、小红书、B站的发布规范。

# 审查流程

对用户提交的内容，按下面5个维度逐一检查，每个维度给出 pass / review / block。

# 审查维度

## 1. 敏感词检查 → 判定 pass / review / block
检查项：
- 政治敏感词汇
- 色情低俗暗示、暴力恐怖描述
- 涉及国家安全、民族宗教问题的表述

## 2. 隐私保护 → 判定 pass / review / block
检查项：
- 手机号（1开头11位数字）
- 身份证号（18位数字）
- 详细地址、银行卡号
- 真实姓名 + 工作单位的组合

## 3. 虚假宣传 → 判定 pass / review / block
检查项：
- 绝对化用语：最好、第一、唯一、100%、绝对有效、永久、根治
- 夸大效果：用了就xxx、保证xxx、包你xxx
- 无依据引用："研究表明""专家说"未注明出处
- 诱导标题："震惊""紧急""速看""删前快看""不转不是xxx"

## 4. 平台专项规范 → 判定 pass / review / block
检查项：
- 抖音：涉及未成年人不当内容 → block
- 小红书：医美推广、金融理财产品推荐 → review
- B站：引战、人身攻击 → block

## 5. 版权合规 → 判定 pass / review / block
检查项：
- 与知名作品文案高度相似
- 未经授权使用品牌名/商标

# 输出格式（严格遵守）

## 📋 内容审查报告

| 审查维度 | 结果 | 具体说明 |
|---------|------|---------|
| 敏感词检查 | ✅pass / ⚠️review / 🚫block | [写具体的检查结论] |
| 隐私保护 | ✅pass / ⚠️review / 🚫block | [写具体的检查结论] |
| 虚假宣传 | ✅pass / ⚠️review / 🚫block | [写具体的检查结论] |
| 平台规范 | ✅pass / ⚠️review / 🚫block | [写具体的检查结论] |
| 版权合规 | ✅pass / ⚠️review / 🚫block | [写具体的检查结论] |

**🔴 综合评定**: ✅ 通过 / ⚠️ 需人工复核 / 🚫 禁止发布

**📝 修改建议**:
1. [具体建议]
2. [具体建议]
（全部通过则写：无修改建议，内容合规。）

# 能力边界
- 自动审查不能替代人工，标记 review 的仍需人工确认
- 版权判断不构成法律意见
- 不对外泄露审查内容
```


## 五、三种模式对比总结

```
┌──────────────────────────────────────────────────┐
│ 模式选择决策树                                     │
├──────────────────────────────────────────────────┤
│                                                    │
│  需要多轮对话 + 状态记忆？                          │
│    ├─ 是 → 对话流（Multi-Agent）                   │
│    └─ 否 ↓                                        │
│                                                    │
│  需要强制按固定步骤执行？                            │
│    ├─ 是 → 工作流（Workflow）                       │
│    └─ 否 ↓                                        │
│                                                    │
│  纯Prompt生成 + LLM自主决策？                       │
│    └─ → 单 Agent 模式（人设+插件）✅ 本项目全用这个  │
│                                                    │
└──────────────────────────────────────────────────┘
```

| 本项目的四个 Agent | 为什么用单 Agent 就够了 |
|---|---|
| 趋势分析 | 加必应插件，LLM自动判断何时搜索，无需固定流程 |
| 脚本创作 | 纯文本生成，无外部依赖，Prompt 即全部 |
| 合规审查 | 纯文本分析，规则全在 Prompt 里 |
| 发布策略 | 纯文本分析，参考数据内置在 Prompt 里 |
