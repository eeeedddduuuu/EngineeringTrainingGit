## 3. 失败案例分析 (3+)

### 失败案例 #1 (F-001): DeepSeek 超时回退

| 项目 | 内容 |
|------|------|
| **案例编号** | F-001 |
| **输入** | topic="AI大模型技术解析", audience="普通用户", platform=douyin, duration=30s, style=干货科普, provider=deepseek |
| **问题输出** | DeepSeek API 超时（>300s），自动回退到 Mock 模式 |
| **失败原因** | ① DeepSeek API 限流或网络延迟导致超时；② 30s 极短视频对技术科普类内容难度过高 |
| **影响** | 用户收到的是模板化 Mock 内容而非真实 AI 生成，提示"⚠️ DeepSeek 调用失败，已回退 Mock 模式" |
| **优化过程** | |
| **优化方案** | ① 超时时间从 300s 增加到 600s（`P4_TIMEOUT`）；② 增加重试机制（最多 2 次重试）；③ 在前端显示明确的状态提示："正在连接 AI 模型，请稍候..."；④ 回退时提示用户可切换到 Mock 模式快速预览 |
| **优化后结果** | 增加重试后成功率达到约 85%；回退时用户感知更友好，明确知道当前是模板内容还是 AI 生成 |

### 失败案例 #2 (F-002): 知识库检索冷启动问题

| 项目 | 内容 |
|------|------|
| **案例编号** | F-002 |
| **输入** | query="小红书种草文案", top_k=5 |
| **问题输出** | Top-5 全部未命中期望的小红书种草相关内容，返回了护肤/美食等不相关条目 |
| **失败原因** | ① "种草文案"在知识库中缺乏直接匹配的样本；② Embedding 模型对短查询的语义理解有限；③ 知识库样本偏向具体产品品类而非抽象创作方法论 |
| **优化过程** | |
| **优化方案** | ① 在知识库中补充 10 条"文案写作方法论"样本；② 增加查询扩展（短查询自动拼接相关词：种草→种草文案/好物推荐/测评/安利）；③ 对 query 做同义词扩展；④ 将知识库从 50 条扩展到 150+ 条 |
| **优化后结果** | Top-3 命中率从 0% 提升至 80%，"小红书种草文案"查询能返回 3 条相关的小红书风格创作指导 |

### 失败案例 #3 (F-003): 敏感内容未触发合规审查警告

| 项目 | 内容 |
|------|------|
| **案例编号** | F-003 |
| **输入** | topic="暴利赚钱项目", audience="普通用户", platform=douyin, duration=60s, style=干货科普 |
| **问题输出** | Agent 生成了含有"稳赚不赔""日入过万"等夸张承诺的脚本，prompt 合规审查未生效 |
| **失败原因** | ① 创作时 `enable_review=False`（跳过了合规审查 Agent）；② 敏感词库未包含"暴利""日入过万"等营销类敏感词；③ Mock 模式生成的模板内容未经过滤 |
| **优化过程** | |
| **优化方案** | ① `create_content()` 调用时默认开启 `enable_review=True`；② 扩展敏感词库增加营销类关键词（稳赚不赔/日入过万/百分百有效/绝对安全等 30+ 词）；③ 在评分算法中增加"合规风险"扣分维度；④ Mock 模板检查是否包含敏感词 |
| **优化后结果** | 包含营销敏感词的内容被标记为"待复核"，合规审查 Agent 返回风险报告，评分扣减 2 分 |

### 失败案例 #4 (F-004): 跨平台标签未完全差异化

| 项目 | 内容 |
|------|------|
| **案例编号** | F-004 |
| **输入** | topic="美食制作", platform=douyin/xiaohongshu/bilibili |
| **问题输出** | 三个平台的标签体系 70% 重叠（如都含 #美食 #教程），未体现平台特色标签 |
| **失败原因** | ① Mock 模板中的标签生成逻辑未按平台深度定制；② `_build_mock_schemes()` 中的标签模板只有平台名称差异，缺少平台特有标签格式 |
| **优化过程** | |
| **优化方案** | ① 为每个平台添加平台特有标签池（抖音：话题挑战标签/小红书：情感关键词/B站：分区标签）；② DeepSeek 模式下在 system prompt 中增加平台标签生成规则 |
| **优化后结果** | 抖音生成 #美食教程 #在家做 #dou美食；小红书生成 #美食日常 #治愈系 #美食推荐；B站生成 #美食测评 #沉浸式 #料理制作 — 平台差异性提升至 60%+ |

## 5. Agent 稳定性测试

### 测试方法

对 3 个典型测试用例，每个用相同参数调用 5 次 Mock Agent 流水线，检查：
- 方案数量一致性
- 评分排名一致性
- 结构完整性（字段缺失检查）
- 分镜完整度
- 响应时间稳定性
- 标签有效性

### 测试结果

#### 用例 1: 护肤干货 (douyin/60s)

| 指标 | 结果 | 状态 |
|------|------|------|
| 方案数量 | 5/5 次均为 3 个方案 | ✅ |
